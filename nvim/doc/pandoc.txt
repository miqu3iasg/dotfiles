NAME
    pandoc - Markdown export to PDF, EPUB, DOCX and HTML

SYNOPSIS
    lua/modules/pandoc.lua             the export module
    pandoc/defaults.yaml               the conversion pipeline
    pandoc/metadata.yaml               default look and language
    pandoc/profiles/<name>.yaml        per-document styles
    pandoc/filters/*.lua               conversion filters
    doc/pandoc.txt                     this page

DESCRIPTION
    modules/pandoc.lua exports the current Markdown buffer by running pandoc asynchronously, so the editor never blocks.
    The buffer is piped through stdin, so unsaved changes are exported too. Success is silent; only pandoc errors and
    warnings are shown. Results go to the exports folder of the project (see lib.txt, the exports module), and open in
    zathura for PDF and EPUB or xdg-open for DOCX and HTML.

    Preview mode builds and opens the document once, then rebuilds it on every save; zathura reloads the file by itself.

    This page describes the export feature itself. The commands are the interface; the keys that trigger them live in
    after/ftplugin/markdown.lua, as the documentation standard (documentation.txt) prescribes.

THE EXPORT PIPELINE
    Every export loads its configuration in a fixed order, where later files win:

        1.  pandoc/defaults.yaml         always loaded; defines the pipeline itself.
        2.  a project defaults.yaml      an optional defaults.yaml in the note's folder or a parent, up to $HOME.
        3.  pandoc/metadata.yaml         default look and language.
        4.  a profile                    requested by name, from pandoc/profiles/.
        5.  the note's YAML front matter  the last word on metadata.

    The project-level file can override the pipeline for a whole folder tree; relative paths inside it resolve from the
    note's directory. One value escapes this order: the file name of the note is injected on the command line, and
    command-line metadata wins over everything, including the front matter.

    The configuration is data, not code: the Lua module orchestrates these files and holds no document logic itself.
    To change the default for every document, edit metadata.yaml; to change a single note, edit its front matter.

THE CONFIGURATION FILES
    defaults.yaml
        The pipeline: Markdown input with the Obsidian extensions (wikilinks, lists without a preceding blank line,
        bare URI autolinks) and with citations disabled, standalone output, XeLaTeX as the PDF engine.

    metadata.yaml
        Default appearance passed as document metadata, so the front matter overrides it: language (pt-BR hyphenation
        needs texlive-langportuguese), article class, 12pt, 2.5 cm margins, 1.5 line spacing, paragraph indent,
        booktabs tables and colored links.

    profiles/
        Layered styles for one export, such as abnt.yaml, an ABNT-like page layout with Times New Roman and justified
        text. A profile is metadata, not options: engine keys such as pdf-engine belong in defaults files, and the
        profile relies on the engine set by defaults.yaml.

THE FILTERS
    wikilinks.lua
        Obsidian wikilinks become their visible text, because a link to a note would point nowhere in the export.
        An alias such as [[Note|alias]] shows the alias; a bare [[Note#heading]] is cut at the anchor and shows only
        the note name, since the heading does not exist in the document; a block reference, [[#^id]], keeps its
        content. Ordinary Markdown links are untouched.

    metadata-block.lua
        Inserts a definition list with the note's reference fields (file name, authors, source, project, tags and
        others) right below the title. Only present fields are rendered, labels follow the primary language subtag
        of `lang`, and URL values become links. The block is disabled for a single note with `show-metadata: false`
        in the front matter. When the note has a `file_name` but no `title`, the file name (without extension) also
        becomes the title.

    Obsidian image embeds, such as ![[img.png|caption]] or ![[img.png|300]], are rewritten into ordinary Markdown
    images before pandoc sees the text, by the export module itself; images are looked up in the note's folder and
    every attachments/ folder above it.

COMMANDS
    :Pandoc [fmt] [profile]      export the current buffer and open the result. fmt is pdf (default), epub, docx
                                 or html; profile is a name from pandoc/profiles/.
    :PandocPreview [fmt] [profile]  like :Pandoc, then rebuild on every save until toggled off.

FILES

    lua/lib/exports.lua             where exports go, shared with VimTeX
    after/ftplugin/markdown.lua     the Markdown buffers that load the module
