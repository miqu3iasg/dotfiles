NAME
    reading - how to read the doc pages of this configuration

DESCRIPTION
    The doc pages are plain text, in the style of a man page: the same sections and lists, with paragraphs written at
    full width and left to the editor's wrap. Meant to be read by simply opening the file, in any editor, with nothing
    rendered.

    The pages, all ending in .txt:

        kickstart.txt       full guide to the config
        structure.txt       the folder structure in depth
        modules.txt         the lua/modules/ layer
        lib.txt             the lua/lib/ layer
        philosophy.txt      why the config builds features from scratch
        documentation.txt   the documentation standard of the config
        development.txt     how to extend the config
        reading.txt         this note

READING BY OPENING THE FILE
    Open doc/kickstart.txt and read. Paragraphs are written as full-width lines, so the editor's soft wrap decides
    where each line breaks; long paragraphs are meant to be seen wrapped, not scrolled sideways. The tradeoff is fixed
    formatting: no bold, no justification, no page header or footer - the man-page style is what you get.

    To jump straight to a section, search for its heading: `/THE TREE`, `/FILES`, and so on. Headings are unique per
    page and appear in the order a man page uses: NAME, SYNOPSIS, DESCRIPTION, then topic sections, then FILES and
    SEE ALSO.

READING EVERY PAGE IN SEQUENCE
    In the shell:

        for p in doc/*.txt; do $EDITOR "$p"; done

    Inside Neovim, one buffer per page, in sequence:

        :args doc/*.txt | argdo edit

WHICH COPY TO EDIT
    There is only one copy: edit doc/<name>.txt directly. If a page contradicts the code or another page, treat the
    divergence like any other bug.

FILES
    doc/<name>.txt          the pages
    doc/documentation.txt   the documentation standard

SEE ALSO
    kickstart(7), documentation(7).
