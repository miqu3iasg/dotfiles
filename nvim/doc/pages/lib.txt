.TH LIB 7 "2026" "nvim config"
.SH NAME
lib \- the lua/lib/ layer: shared utilities and domain logic
.SH SYNOPSIS
.nf
man \-l doc/pages/lib.txt
:read !man \-l doc/pages/lib.txt
.fi
.SH DESCRIPTION
.PP
\fIlua/lib/\fR holds everything that exists to be required by other
modules: reusable helpers, shared state and domain logic that more
than one feature needs. It is the bottom of the layer stack
(init.lua > config > plugins > modules > lib) and nothing in it
requires upwards, ever.
.PP
The criterion is binary: a file that exposes commands, autocmds or
keymaps is a module (\fIlua/modules/\fR), anything else is a lib.
Two consequences shape the layer:
.IP \(bu 2
lib files register nothing global by default. The one exception is
\fIlib/lazy.lua\fR, which registers a single FileType autocmd as its
whole job and owns it completely \- the documented exception, not a
loophole.
.IP \(bu 2
Shared state lives here when several features must agree on it,
with one file as its single source of truth (\fIlib/autoformat.lua\fR
and \fIlib/exports.lua\fR are the examples).
.SH THE LIBRARIES
.TP
.I buffers
Helpers to inspect, save and delete buffers without breaking the
window layout. A buffer is saved only when it has unsaved changes
and a real file name; deleting a buffer keeps every window that
showed it, each switching to the most recently used buffer or a
fresh empty one; bulk deletes save first and keep anything whose
save failed, reporting the count.
API: M.is_terminal, M.is_normal_window, M.save_if_modified,
M.delete, M.pick_replacement, M.delete_keep_layout, M.delete_where.
.TP
.I bigfile
Decides whether a buffer is big (1.5 MiB file size or
1000-character lines, sampled over 200 lines) and caches the
verdict in \fBvim.b.bigfile\fR. Every feature that needs to switch
off on big buffers asks this module, so the thresholds are defined
once. API: M.is_big.
.TP
.I lazy
The filetype-based lazy loader for vim.pack plugins, the only
indirection in the config. Plugins declare themselves through
M.setup{ src, filetypes, version, configure, after }; the plugin is
installed at startup, but its plugin/ scripts only run when the
first buffer of a declared filetype appears. Loading runs
\fIconfigure\fR, then \fB:packadd\fR, then \fIafter\fR, then fires
the FileType event again for the triggering buffer. Inspect every
lazy plugin with \fB:autocmd LazyPack\fR. API: M.setup, M.load.
.TP
.I autoformat
Single source of truth of the autoformat-on-save state, with two
scopes: global (\fBvim.g.disable_autoformat\fR) and buffer-local
(\fBvim.b.disable_autoformat\fR); formatting runs only when neither
disables it. The buffer-local scope is the buffer override, set by
per-filetype opt-outs; \fB:FormatEnable\fR and \fB:FormatDisable\fR
act on the global scope. API: M.enabled, M.enable, M.disable,
M.toggle.
.TP
.I substitute
Builds \fB:substitute\fR command lines: escapes patterns, reads the
visual selection and pre-fills the command line with either a
buffer substitution or a project-wide one (the latter needs ripgrep
as \fIgrepprg\fR). The editing keymaps call this from
\fIconfig/keymaps/\fR. API: M.escape_pattern, M.prompt, M.project,
M.selection, M.get_visual.
.TP
.I exports
Single source of truth for where exported documents go, shared by
the pandoc, vimtex and tinymist setups, so three features write to
the same layout. Documents go to
\fI<root>/exports/<reldir>/<name>.<ext>\fR and latexmk byproducts
to \fI<root>/.build/<reldir>/<name>/\fR; <root> is found through
the project markers in M.markers, falling back to the file's own
folder, or forced globally with \fBvim.g.exports_root\fR. An
unnamed buffer is treated as a file called \(gascratch\(ga.
API: M.root, M.basename, M.exports_dir, M.reldir, M.output_path,
M.output_pattern, M.build_dir.
.TP
.I system
Host system detection: M.get_os returns "windows", "mac" or "linux"
(everything that is neither, including the BSDs), so OS-specific
behavior is asked, not guessed per file.
.SH USING LIB WELL
.IP \(bu 2
Before writing a helper, look here first; a duplicated helper is a
layer violation waiting to happen.
.IP \(bu 2
When two features disagree about a piece of state, the fix is not a
flag: move the state into a lib file as its single source of truth
and let both ask it (the autoformat module exists for exactly this
reason).
.IP \(bu 2
When a lib helper starts wanting a command or an autocmd of its
own, that is the signal it became a feature: move it to
\fImodules/\fR.
.IP \(bu 2
Keep the header standard (see \fIdoc/pages/documentation.txt\fR): a lib
file is read by strangers more often than any other file.
