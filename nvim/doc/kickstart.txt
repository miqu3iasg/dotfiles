NAME
    kickstart - guide to this hand-rolled Neovim configuration

SYNOPSIS
    man -l doc/kickstart.txt        read this page in a terminal
    :read !man -l doc/kickstart.txt read it inside Neovim

DESCRIPTION
    A hand-rolled Neovim configuration built on the native plugin
    manager (`vim.pack`), the native LSP stack (`vim.lsp.config` /
    `vim.lsp.enable`) and a small set of deliberately chosen plugins.
    There is no distribution and no lazy-loading framework; the one bit
    of lazy loading (heavy filetype-bound plugins) is a few lines in
    lua/lib/lazy.lua. Every module is small and every `require` is
    explicit, which keeps startup around 70-80 ms.

    Keymaps are deliberately not documented here: they change often, and
    a stale keymap list is worse than none. The live source of truth is
    the matching file in lua/config/keymaps/ and `:map`. Everything else
    about the config is described below.

STARTUP
    init.lua only fixes the load order:

        1.  vim.loader.enable(), vim.deprecate disabled
        2.  config.options     global editor options
        3.  config.keymaps     leader keys and keymap modules
        4.  config.autocmds    global autocmds
        5.  config.commands    user commands
        6.  modules.statusline native statusline
        7.  modules.scratch    persistent scratch buffer
        8.  config.pack        vim.pack plugin declarations
        9.  plugins            one adapter file per plugin suite
        10. modules.compile    :Compile / :Recompile
        11. colorscheme hollow

    Nothing else runs at startup. Lazily loaded plugins attach later,
    when the first buffer of a declared filetype appears (see LAZY
    LOADING).

DIRECTORY LAYOUT
    init.lua              load order only
    colors/               custom colorschemes
    after/ftplugin/       buffer-local options per filetype, applied
                          after the runtime ftplugins
    after/queries/        Tree-sitter query overrides
    lua/config/           editor behavior loaded at startup
    lua/plugins/          one adapter file per third-party plugin suite
    lua/modules/          self-contained components written for this
                          config; each exposes setup() and owns its own
                          state
    lua/lib/              helpers and domain logic used by other
                          modules; exposes no commands, autocmds or
                          keymaps
    lua/language/         language server stack; one module per server
                          under servers/
    lua/snippets/         LuaSnip snippets, one file per filetype
    lua/archived/         deprecated modules kept off the runtimepath
    pandoc/               Pandoc defaults, metadata, profiles and Lua
                          filters
    resources/            example external-tool configuration files
    spell/                custom spell files
    nvim-pack-lock.json   revision lock file written by vim.pack
    doc/                  man pages (this folder)

    The layer rule is binary: a module that exposes commands, autocmds
    or keymaps goes in modules/; anything else goes in lib/. A layer may
    only require the layers below it: init.lua, then config, plugins,
    modules and lib. Nothing in lib/ requires upwards.

OPTIONS
    Highlights of lua/config/options.lua. The full list is in the file
    itself; each option's help is available with `:help 'name'`.

    Editing
        'clipboard'   unnamedplus: yanks go to the system clipboard
        'expandtab'   4-space indentation by default; vim-sleuth detects
                      the existing style of each file
        'undofile'    persistent undo with 10000 levels; because of it,
                      'swapfile' and 'backup' are off
        'foldmethod'  manual, every fold starts open
        'nrformats'   octal removed, so `Ctrl-A` on `007` does not
                      increment to `010`

    Search
        'ignorecase'/'smartcase' case-insensitive unless the pattern has
        uppercase; ripgrep is used as 'grepprg' when installed, which
        the project-wide features rely on.

    Display
        'list' with tabs, trailing spaces, spaces and non-breaking
        spaces marked; 'scrolloff' 4; no number columns; single window
        borders; block cursor everywhere ('guicursor'); 'termguicolors'.

    Navigation
        'path' includes **, making `:find` and `gf` recursive;
        'switchbuf' uselast, so buffer jumps reuse the window that last
        showed the buffer; splits go right and below.

    Sessions
        'sessionoptions' is fixed here and must match what
        modules/sessions.lua saves and restores.

AUTOCMDS
    Global autocmds live in lua/config/autocmds.lua, grouped per concern
    with named augroups:

        VimResized      keep splits evenly sized after a terminal resize
        TextYankPost    highlight yanked text
        FileType        do not continue comments on new lines
        FileType        disable heavy features on big files (see
                        lua/lib/bigfile.lua): Treesitter, completion,
                        diagnostics, folds and spell go off
        BufRead         .env files get dosini highlighting
        VimEnter        startup behavior: inside tmux, restore the
                        session of the directory; otherwise open the
                        file explorer, also when launched with a single
                        directory argument
        VimLeavePre     save the session of the current directory, tmux
                        only
        BufWritePre     create missing parent directories on save
        BufReadPost     jump to the last cursor position, except in git
                        commit buffers
        BufWritePre     strip trailing whitespace, skipping special and
                        non-modifiable buffers
        FileType        utility buffers (help, quickfix, man, undotree,
                        Fugitive views, health, ...) are unlisted and
                        close with q or <Esc>; listchars are off in them
        TermOpen        terminals start in insert mode with a clean UI
        FileType        the built-in undotree opens on the far left with
                        a fixed width of 40 columns

USER COMMANDS
    Global user commands (lua/config/commands.lua):

        :Setwd                change the working directory to the
                              current file's directory
        :FormatEnable         re-enable autoformat on save
        :FormatDisable        disable autoformat on save
        :PackAdd {repos}      add plugins to the session, installing
                              the missing ones
        :PackDel {names}      delete plugins by name
        :PackUpdate [names]   update all plugins, or only the named ones

    Buffer-local and module commands:

        :Compile [cmd]        run a build command asynchronously into
                              *compilation*; without an argument it
                              prompts pre-filled with the default for
                              the filetype (see COMPILATION)
        :Recompile            rerun the last command of this directory
        :CompileInterrupt     kill the running command of this directory
        :Scratch              toggle the scratch buffer
        :ScratchSplit         open the scratch in a vertical split
        :Scratch!             wipe the scratch buffer
        :Pandoc [profile]     export the current buffer (see PANDOC),
                              buffer-local
        :PandocPreview        export on every save and open the result,
                              buffer-local
        :NotesDraft           create a quick draft (see NOTES)
        :NotesNew             create a typed note from a template
        :NotesTemplate        insert a template into the current note
        :NotesFiles           find notes by name
        :NotesGrep            search note contents
        :NotesLast            reopen the last visited note
        :NotesOpen            open the vault folder

PLUGIN MANAGEMENT
    Plugins are managed by Neovim's built-in package manager, `vim.pack`.
    There is no third-party plugin manager and no lockfile tooling beyond
    the revision file `nvim-pack-lock.json` that vim.pack itself writes.

    Eager plugins are declared in lua/config/pack.lua with a short
    comment per plugin. Everything they need at install time runs in a
    PackChanged autocmd created in the same file: nvim-treesitter gets
    `:TSUpdate` and LuaSnip builds `jsregexp` with `make
    install_jsregexp`, which needs a C toolchain and only warns on
    failure. A plugin that needs a build step must be handled there.

    Lazy loading is the only indirection in the config, and it is a
    single helper, lua/lib/lazy.lua. A lazy plugin declares itself at
    the bottom of its own adapter file:

        require("lib.lazy").setup{
            src = "https://github.com/...",   -- vim.pack source
            filetypes = { "tex" },            -- load triggers
            configure = function() ... end,   -- runs before :packadd
            after = function() ... end,       -- runs after :packadd
        }

    The plugin is installed at startup but its plugin/ scripts only run
    when the first buffer of one of the filetypes appears. Loading runs
    configure, then :packadd, then after, and then fires the FileType
    event again for the triggering buffer, because the plugin was not on
    the runtimepath when the original event ran. All lazy plugins are
    inspectable in one place with `:autocmd LazyPack`.

    To update every plugin: `:PackUpdate` or `:lua vim.pack.update()`.

THE PLUGIN SET
    File explorer
        canola.nvim, a fork of oil.nvim: the filesystem is edited as a
        normal buffer, replacing netrw. Deletions go to the trash and
        simple edits are applied without confirmation. Entries open with
        an extension-specific viewer (zathura, imv, mpv), falling back
        to xdg-open. See lua/plugins/oil.lua.

    Tree-sitter
        nvim-treesitter for syntax-aware parsing and highlighting, plus
        nvim-treesitter-textobjects for motions and selections. Parsers
        are requested for automatic installation in
        lua/plugins/treesitter.lua (max 4 concurrent jobs); highlighting
        per filetype is activated separately. TeX buffers keep Vim's
        legacy syntax engine because VimTeX depends on its highlight
        groups. Needs the tree-sitter CLI on PATH.

    Completion and snippets
        No completion plugin: native LSP completion plus LuaSnip. The
        menu's only source is the LSP; LuaSnip's own snippets are
        expanded by trigger, autosnippet or snippet keymaps. The menu
        opens automatically only on the filetypes listed in
        TRIGGER_FILETYPES (lua/plugins/completions.lua); elsewhere
        completion is manual and the omnifunc still works. Snippet
        definitions live in lua/snippets/, one file per filetype, loaded
        lazily; shared helpers are in lua/snippets/common.lua.

    Formatting and linting
        conform.nvim runs external formatters on demand and on save,
        with a chain per filetype in lua/plugins/formatting.lua: stylua
        (Lua), goimports-reviser + golines (Go), clang-format (C/C++),
        astyle (Java), ruff (Python), prettierd (web), yamlfmt, taplo,
        sql-formatter, latexindent, typstyle, asmfmt and others, with
        trim_whitespace and trim_newlines as the fallback chain for
        every filetype. The on/off state lives in lib/autoformat.lua
        with global and buffer-local scopes (:FormatEnable,
        :FormatDisable). External linters run through nvim-lint
        (lua/language/lint.lua); Python is linted with ruff, which is
        the same tool conform formats with.

    Language servers
        See LANGUAGE SERVERS.

    Fuzzy finder
        fzf-lua wraps fzf for files, buffers, grep, diagnostics, help
        and LSP results. Needs fzf, grep, ripgrep and fd. lib/substitute
        also calls ripgrep directly for project-wide substitutions.

    Git
        vim-fugitive for repository operations (staging, committing,
        diffing, blaming), vim-rhubarb so :GBrowse builds GitHub URLs,
        and gitsigns.nvim for hunk-level markers, staging and blame.
        fzf-lua-based browsing is registered only when fzf-lua is
        available. Destructive remote operations are left to the
        terminal. See lua/plugins/git.lua.

    Markdown and notes
        obsidian.nvim for wikilinks, completion and vault features;
        img-clip.nvim pastes clipboard images into files. The note
        creation and search workflow is a config module, NOTES below.

    LaTeX
        VimTeX, loaded lazily on the first tex buffer: compilation, PDF
        viewer sync, motions, folding, table of contents, and a hook
        that copies the compiled PDF to exports/. Needs a TeX Live
        installation and a SyncTeX viewer (zathura).

    Typst
        tinymist, through the LSP stack; PDF export needs the typst CLI
        and formatting needs typstyle.

    Lisp
        Conjure, loaded lazily for Scheme, Common Lisp, Racket and
        Clojure, configured for MIT Scheme as the REPL.

    Small quality-of-life plugins
        lua/plugins/unnecessary-shit.lua: mini.nvim (surround, pairs,
        icons and other small modules), vim-tmux-navigator (splits and
        tmux panes share one navigation, the tmux side needs the
        matching plugin), nvim-colorizer.lua (inline color preview),
        flash.nvim (label-based jumps), vim-sleuth (indentation
        detection), markdown-preview.nvim (browser rendering, used to
        read documentation with mermaid diagrams), lazydev.nvim (Neovim
        API types for lua_ls).

    Colorschemes
        Custom colorschemes live in colors/: hollow (the default),
        brightburn, classic, artifact, enfocadomod and insanity. Extra
        third-party schemes (fogbell, eyes.nvim, black-metal,
        gruber-darker-renaissance) are installed from pack.lua.

LANGUAGE SERVERS
    The stack is in lua/language/. One module per server under
    servers/:

        clangd (C/C++), cssls, emmet_language_server, eslint, gopls
        (Go), html, lua_ls (with lazydev.nvim), marksman (Markdown),
        pyright (Python), tailwindcss, texlab (LaTeX), tinymist (Typst)
        and vtsls (TypeScript/JavaScript).

    lua/language/init.lua holds the shared setup: mason.nvim installs
    the servers (scheduled after startup, automatic_enable off), the
    shape of each module is validated (a malformed module becomes a
    startup error instead of a broken attach), each config is passed to
    vim.lsp.config, and one LspAttach autocmd sets the buffer-local LSP
    behavior. Most native LSP mappings are kept as-is; a few are
    replaced by fzf-lua pickers.

    Server modules follow the UserLspServerModule contract in
    lua/language/types.lua: a `config` table for vim.lsp.config and an
    optional `on_attach(client, bufnr)` hook.

    Java is special: jdtls is installed through Mason but started by its
    own module, lua/language/servers/jdtls.lua, never by this stack, so
    the LSP toggle leaves it alone.

    Other stack-wide decisions:

        - dynamic workspace file watching is disabled, so servers do not
          register thousands of watchers in large projects;
        - formatting never goes through the servers, only through
          conform;
        - diagnostics start globally disabled: no underlines or signs
          until the display is toggled on;
        - the whole stack can be enabled/disabled at once (clients are
          stopped, not just detached).

    Python is also linted by ruff through nvim-lint, outside the LSP
    stack and with its own toggle (lua/language/lint.lua).

COMPILATION
    modules/compile.lua provides an Emacs-like :Compile. It runs a
    build command asynchronously through `sh -c` and streams its output
    into a *compilation* buffer in a bottom 25-line split; the buffer
    gets the qf filetype and shares the utility-buffer close behavior.
    When the command exits nonzero, the output is parsed into the
    quickfix list; gcc/clang, javac and Python tracebacks are parsed,
    anything else still shows in the buffer.

    State is per working directory: starting a new compile in the same
    directory kills the previous process, :Recompile reruns the last
    command, :CompileInterrupt kills the current one. Without an
    argument, :Compile prompts pre-filled with the filetype default
    (`make -k`, `python %`, `cc -o %:r.out %`, `go run %`, ...).

SESSIONS
    modules/sessions.lua is a minimal, fully automatic, per-directory
    session manager built on :mksession and :source, active only inside
    tmux. On VimEnter with no file arguments it restores the session of
    the directory; on exit it saves it. Files live in
    stdpath("state")/sessions/, one per cwd (the path is flattened into
    a single file name).

    A save happens only when at least one real file buffer is open, so
    opening and closing Neovim on the explorer alone never overwrites an
    existing session. gitcommit/gitrebase buffers are ignored and Oil
    buffers are removed before saving. 'sessionoptions' is set once in
    options.lua and must stay in sync with this module.

SCRATCH BUFFER
    modules/scratch.lua keeps a single persistent scratch buffer for
    throwaway notes and pastes. Toggling replaces the buffer of the
    current window (only when it is a regular file buffer; special
    buffers like Oil, terminals and Fugitive views get a vertical split
    instead), and leaving it restores the previous buffer, so the window
    layout never changes. The buffer is hidden, not wiped, and lasts
    until the session ends or :Scratch! deletes it. Inside the scratch,
    q and <Esc> leave it.

PANDOC
    modules/pandoc.lua exports the current Markdown buffer to PDF, EPUB,
    DOCX or HTML by running pandoc asynchronously, so the editor never
    blocks. The buffer is piped through stdin, so unsaved changes are
    exported too. Results go to the exports folder (see lib/exports.lua)
    and open in zathura (PDF/EPUB) or xdg-open (DOCX/HTML).

    Preview mode builds and opens the document once, then rebuilds it on
    every save; zathura reloads by itself. Each export loads, in order:
    the pipeline in pandoc/defaults.yaml, an optional defaults.yaml in
    the note's folder or a parent, pandoc/metadata.yaml (default layout
    and language), and a profile from pandoc/profiles/ when one is
    named. Filters in pandoc/filters/ handle wikilinks, metadata blocks
    and citations rendered as plain text; profiles/abnt.yaml covers
    ABNT-styled documents. Needs pandoc-cli and zathura.

NOTES
    modules/notes.lua is a flat vault of Markdown notes managed from
    Neovim: quick drafts and typed notes from user-maintained templates,
    template insertion into an existing note, search by name and by
    content, and reopening the last note. The vault is just a folder:
    $ARCANUM_DIR, or ~/dev/arcanum when unset, and it must already
    exist. Notes live in the vault root, templates in _templates/, and
    pasted images in attachments/.

    File names follow TYPE-YYYYMMDD-HHmmss[-SLUG].md, defined by the
    vault's own README. Placeholders available to templates: {{title}},
    {{date}}, {{id}}, {{adr_number}}. Creation is bound to the vault,
    but template insertion works on any Markdown file on disk.

MISC MODULES
    statusline     native 'statusline', no plugin. The active window
                   shows editor state, position, search and selection
                   info, git branch, diagnostics and macro recording;
                   inactive windows get a reduced version. Costly pieces
                   are cached: mode in vim.g.sl_mode, branch in
                   vim.b.git_branch (looked up asynchronously, cached
                   per directory), file size in vim.b.sl_file_size (read
                   from disk, so it is stale until save).

    window_zoom    zooms the focused window by showing it as the only
                   window of a new tab, the original layout staying
                   intact in its own tab. Toggling again closes the zoom
                   tab. The state is the tabpage-local t:zoomed, which
                   the statusline reads, and closing the tab by any
                   other means also ends the zoom.

    close_view     closes Fugitive views (index, status, blame, commit
                   buffers) without ever quitting Neovim; closing a
                   commit buffer discards it and aborts the commit.

    markdown_lists native list editing for Markdown buffers: cycling,
                   promoting and demoting list items on the current
                   line or selection, with formatter helpers that keep
                   markers and indentation as written. The bullet of new
                   items is set with vim.g.markdown_list_bullet and the
                   delimiter with vim.g.markdown_list_delimiter
                   (buffer-local versions take precedence).

    asm_align      column alignment for assembly buffers, a direct port
                   of the layout asmfmt produces: tabs for indentation,
                   spaces for alignment, per-block operand columns and
                   end-of-line comments aligned to one column. Lines are
                   never added, removed or reordered; structural changes
                   are left to asmfmt, which conform runs on format.

LIB
    lua/lib/ holds everything that exists to be required by other
    modules:

        buffers       inspect, save and delete buffers without breaking
                      the window layout; deleting a buffer keeps its
                      windows, which switch to the most recently used
                      buffer
        bigfile       decides whether a buffer is big (1.5 MiB size or
                      1000-character lines, sampled over 200 lines);
                      the verdict is cached in vim.b.bigfile
        lazy          the lazy loader (see PLUGIN MANAGEMENT)
        autoformat    single source of truth of the autoformat state,
                      with global and buffer-local scopes
        substitute    pre-fills :substitute or a project-wide
                      substitution on the command line; needs ripgrep
        exports       single source of truth for export paths, shared by
                      pandoc, vimtex and tinymist: documents go to
                      <root>/exports/<reldir>/ and latexmk byproducts to
                      <root>/.build/<reldir>/; <root> is found through
                      markers or forced with vim.g.exports_root
        system        OS name detection

FILETYPE OVERRIDES
    after/ftplugin/<ft>.lua holds buffer-local options for each
    filetype, applied after the runtime ftplugins: PEP 8 for Python,
    gofmt style for Go, per-language comment and fold settings, toolchain
    commands, and so on. Logic shared by two or more filetypes goes in
    lib/ instead. after/queries/ holds Tree-sitter query overrides,
    such as Markdown text objects.

REQUIREMENTS
    Neovim 0.12 or newer. Everything else is per feature and documented
    in the header of the file that uses it. On Arch Linux:

        sudo pacman -S git tmux fzf ripgrep fd nodejs npm jdk21-openjdk \
          clang go typst typstyle texlive-basic texlive-latex \
          texlive-latexextra texlive-binextra pandoc-cli zathura \
          zathura-pdf-mupdf

    Language servers, formatters and linters are installed through
    Mason (:MasonInstall ...), and the requests happen automatically at
    startup for the servers declared in the LSP stack. Notes: LuaSnip
    needs a C toolchain at install time; jdtls needs Python 3; Tree-
    sitter needs the tree-sitter CLI.
